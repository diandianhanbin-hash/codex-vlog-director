# 多场景精彩片段决策器

输入是上游的实际画面/声音描述和源时间戳；不自行假装已观看原片，也不直接执行 FFmpeg。只有原视频时先用 [分析技能](../ffmpeg-analyse-video/SKILL.md)。

## 选择场景规则

从用户或导演传入的 `scene_type` 选择并读取一份规则：

- `outdoor-hiking`：[户外徒步](../vlog-director/references/scenes/outdoor-hiking.md)。
- `family-entertainment`：[家庭娱乐](../vlog-director/references/scenes/family-entertainment.md)。

明确的用户类型优先，不因技能原名或评分里的行程概念而改为徒步。独立调用时类型不清才询问；用户要求分析/分镜即有该阶段授权，不需要再次确认。每次只加载适用模式；混合素材逐段标明模式。

## 决策流程

1. 统一候选片段，保留 `source_file`、源起止、实际描述、音频证据、置信度与观察密度。时间/身份/原因冲突记入 `evidence_notes`，不自行改写事实。
2. 按场景分配故事角色。按 `visual / event / progression / emotion / story / uniqueness / quality` 七维1–5分说明价值，**不计算总分，不用固定权重**。没有证据或无法判断的维度使用 `null`，不要为了凑齐七项默认填3分；有证据的价值评价仍可使用判断分并写理由。`progression` 在徒步指路线推进，在家庭指活动推进；旧输入 `journey` 可按已选模式解释，不要求家庭存在行程。
3. 按语义归相似组，比较事件阶段、实际变化、故事作用、人物/声音和质量。用所选场景的去重逻辑，不只比较颜色、机位或背景。
4. 对候选给出 `must_keep / keep / optional / drop`。用户必留且确有证据的片段优先；重要真实事件与必要上下文优先于美观。技术差但唯一的核心事件可保留；仅重复且没有新信息的片段可删除。
5. 推荐源入出点，保留完整动作、景观揭示过程或对白/反应链。若抽帧太稀、声音缺失或情绪有歧义，向上游提出明确的密查源区间；可以先出带限制的分镜，但不把未确认事件标为已确认。切点低置信时标记，不凭秒级样本声称逐帧准确。
6. 只用所选场景的故事检查项检查覆盖；缺少原始证据用 `not_available`，有证据但计划遗漏用 `missing`。避免为了模板完整编造登顶、安抚、胜负或情绪恢复。
7. 按目标时长先去重复、缩等待/过渡，再调整非关键片段。不可切断核心语义或动作以机械达标；必留内容确实超时则报告最小合理时长和取舍。预算计入转场重叠，区分源片保留长度与预计成片时间。
8. 按 [输出契约](references/output-contract.md) 保存 `storyboard.md`、`storyboard.csv` 和 `edit-plan.yaml`，交给共用 [剪辑执行](../ffmpeg-skill/SKILL.md)。分析报告由上游保存，分镜明确引用证据。用户只要分镜时不进行视频渲染。

## 声音、构图与分镜建议

建议记录在分镜和交接中，不直接执行：实际现场声保留位置、需核对的对白、合理源画面裁切、适用配乐氛围与音量避让。用户提供 BGM 说明则引用其中选曲依据。不要把编辑字幕、近景裁切或音乐当作已存在的拍摄事实。
